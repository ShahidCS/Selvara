# Security and edge-case audit, 2026-11-26

Scope: the whole repository at `main` 6100eaf (v0.3.3 plus the framework register change), production API (`front-end/src/server`),
browser app, Supabase migrations, CI configuration. Method: read the code and configuration for each item, then prove the judgement with a
test (unit, end to end, database or a command). Phase A follows the requested checklist (loosely OWASP ASVS 4.0); Phase B the requested edge
cases. Every fix is one commit naming its item; every fix is a **draft that needs human security and code review before deployment**.

Several items are partly verified and partly open; they are counted where their main finding sits and the open part is listed in section 4.

Top 5 risks remaining:

1. **Lost updates (EDGE-18, Medium).** Edits do not carry the version the person loaded, so a save from an older copy (a second device, a stale tab) silently replaces a newer change to a policy, risk or control. A known-failing test records it.
2. **"Today" is UTC (EDGE-16, Medium).** Due and overdue labels and date checks ("expiry must be in the future") use the UTC date, so near midnight people far from UTC see the wrong state or have a valid date refused.
3. **Uploads are not scanned for malware (SEC-18, Medium).** Type, size and content are checked and files are served only through short signed links, but a file shared with auditors or through the Trust Center is not scanned.
4. **Double submissions on slow connections (EDGE-11 residual, Medium/Low).** About 82 primary buttons outside the AI, vendor and control modals still accept a second click while saving.
5. **No account erasure (EDGE-19, Medium, privacy).** A person can be removed from a company but there is no deletion or anonymisation of their account; erasure conflicts with the append-only audit log and needs a retention decision.

## 5. Actions for the owner

1. **Decisions:** time zone model (EDGE-16); versioned edits (EDGE-18); malware-scanning provider (SEC-18); retention and erasure (EDGE-19); alias and ban policy (EDGE-20); Arabic and right-to-left (EDGE-14).
2. **Approve** the development dependency update for `typescript-eslint` / `minimatch` (SEC-21).
3. **Verify in Supabase** (Authentication settings): the email OTP and recovery link expiry is 3600 seconds or less (SEC-17 now also enforces 60 minutes on the server). Password hashing is managed by Supabase (bcrypt); no action unless your plan offers a setting.
4. **Verify the HTTPS redirect** on each production hostname: `curl -sI http://<your production host>/` should answer 301 or 308 with `Location: https://...`.
5. **Monitoring:** ship the function logs to your SIEM and alert on bursts of `auth.sign-in.failed`, `auth.account.locked`, `access.denied` and `rate.limited` (control LOG-06).
6. **Deployment note for SEC-17:** reset links requested before this change is deployed have no server record, so they stop working; people who just asked for a reset must ask again.
7. **Key rotation:** none needed (SEC-24/25 found no secret in the history).
8. **App Store / Play:** not applicable (web application).
9. **Review:** every fix here needs human security and code review before deployment.
