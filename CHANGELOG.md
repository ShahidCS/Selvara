# Changelog

All notable changes are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and versions follow [Semantic Versioning](https://semver.org/). Releases are cut from signed tags (see [docs/security/PIPELINE.md](docs/security/PIPELINE.md)).

## [Unreleased]

### Changed
- **New app frame (reference review, part 1 of 5).** The sidebar sits on the canvas and each page is one rounded panel. The breadcrumb is a small line at the top of the panel, and page titles are larger and lighter. Cards have larger corners and no shadow.
- **Header row.** A pill shows how many approvals are waiting for you (the same figure as My Work) and opens My Work. A Help menu holds "Take the tour of this page" and the keyboard shortcuts. The theme switch moved into the account menu. Search stays as the icon it was.
- **Overview greets you** by first name, with the date above.
- **Lists.** People are shown with their initials, and vendors with a letter tile (logos come with the Settings release). Cells can carry a second line, such as the controls an issue is linked to. Less-used filters wait under "+ Add filter" (Due on Issues, Device on People, Collected by on Evidence). A "Sorted by" control shows and changes the order. Severity in issue lists, findings tables and the risk register is shown as signal bars with the word. The Issues Table/Kanban switch is in the page header.
- **One AI mark** (a ringed dot) is used wherever AI content or an AI action appears.

## [0.2.4] - 2026-11-22

Sidebar and production loading fixes; no migration and no new environment variable. Deploy as usual.

### Fixed
- **Every module is in view in the sidebar.** All sidebar groups now start open, for company admins and platform super admins alike, instead of only the group of the current page. With the other groups closed, the expanded sidebar showed only group names (Assurance, Internal Risk, Platform Security…) and the modules looked missing. A group someone closes stays closed for the session.
- **Production waits for the server before acting on the role.** Until the server has confirmed the session, the app no longer redirects, shows a page or loads data from the role this browser last saved (it may be an older role or another account's). A link straight to a module, such as `/ws/frameworks`, now opens it instead of sending the person to the Overview.
- **One module that fails to load no longer empties the others.** Each module's records are loaded on their own; if one fails, the others still load and a message at the top of the page names what could not be loaded, with Reload. Before, one failure left every module empty with no message.
- **Platform staff no longer ask for company data.** The Admin Console loaded company records it may not read (refused with 403 errors in the browser console).

## [0.2.3] - 2026-11-22

Layout and guided-tour fixes, and documentation brought up to date with the server; no migration and no new environment variable. Deploy as usual.

### Fixed
- **Guided tours follow the page.** The ring and bubble stay on their element when the sidebar collapses or expands, the page scrolls or content loads, instead of staying where they first appeared. A layout change that moves the element out of view brings it back; the bubble never leaves the window, the ring never covers the top bar, and the app frame no longer shifts up when a tall area is shown. Popovers and the collapsed-rail flyouts follow their trigger the same way.
- **Layouts fit the space beside the sidebar.** Pages respond to the width of the content rather than the window, so with the sidebar open on a tablet or small laptop cards stack instead of being squeezed or cut off, and nothing pushes the window sideways. KPI change pills and long figures fit their tile, card headers and colour pickers wrap, and wide tables scroll inside their card. Findings and fixes: [UI review, group G](docs/architecture/ui-review/G.md).

### Documentation
- **The docs no longer say there is no backend.** `README.md` (status, tech stack, testing, project status, roadmap), `AGENTS.md`, `docs/security/SECURITY.md` (known limitations) and `docs/guides/TESTING.md` now describe the server that every module runs on, what production still needs (owner setup, review, scheduled jobs, malware scanning) and what the tests cover. The production programme's progress table shows group 8b as merged.
