# Changelog

All notable changes are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and versions follow [Semantic Versioning](https://semver.org/). Releases are cut from signed tags (see [docs/security/PIPELINE.md](docs/security/PIPELINE.md)).

## [Unreleased]

### Changed
- Phase 5, step 1: decisions from the bell. A pending workspace approval that the signed-in person may decide now carries Approve and Reject in the notifications panel, with a reason of at least 10 characters. It uses the module's own decision function and the engine's rules, so nobody sees their own request or one about themselves, and the change is applied only on the final approval. Offered for AI governance, vendors, API, assistant, reports, trust and questionnaires approvals; access, people, team, MFA, risk, policy, issue, control, evidence and platform approvals have module-specific rules and still open their record. `approvalKit.decideApproval` now refuses an approval that has no registered handler before recording it, so an approval cannot be stored as approved and never applied. 9 unit tests and 3 end-to-end tests added. Protected files (`rbac.ts`, `approvals.ts`, `sod.ts`) were not changed in this step.
- Text inside the Security Controls groups had no padding (the group's text block was nested one level below the rule that pads a card), so it touched the card edge; it now has 16px on every side. The Integrations Connect button's accessible name now contains its visible text ("Connect read-only: <name>"). 1 end-to-end test added.
- Phase 6, step 2: automated accessibility tests and workspace colour (right-to-left and Arabic are deliberately excluded for now). Added the dev dependency `@axe-core/playwright` 4.14.0 (axe-core 4.14.0, MPL-2.0, allowed by the licence policy for dev dependencies only; not in the shipped build). `e2e/a11y.spec.ts` runs axe (WCAG 2.0 to 2.2 A and AA) on every workspace and admin route, the new record and form pages, the sign-in and vendor-portal pages, and the open notifications panel, module palette and shortcut list, in light and dark; serious or critical findings fail the build. It found and this change fixes: the bell and account buttons and several buttons whose accessible name did not contain their visible text (the bell now reads "9+ unread" when the badge says 9+), low-contrast badge, avatar, tab counts and heat-map cells, an empty tooltip, unnamed usage meters, scrollable regions with no keyboard access (tables get a tab stop only when they actually scroll), line and bar chart marks inside an `img` role (the chart body is now a labelled group so the marks stay focusable), and a paragraph inside a definition list. Workspace colour: Team, Review cycles & SLAs gains a Workspace colour choice (Violet default, Blue, Teal, Green, Slate). It is not free-form: only these presets can be chosen, each overrides the six `--c-brand-*` variables and the dark accent set, and `tests/unit/brand.test.ts` computes 4.5:1 contrast for every text pair in both themes. Admin only, audited (`team.brand.changed`, before and after), applied in the workspace only (the Admin Console, sign-in and vendor portal keep the platform colour). The Overview control-coverage heat map now uses ink text on a lighter tint so it reads under every colour. 13 unit tests and 99 end-to-end tests added.
- Phase 6, step 1: display preferences. The profile menu gains Compact density (a checkbox item): table rows, table headers and KPI tiles tighten through three variables (`--cell-y`, `--head-y`, `--tile-y`) set on `<html data-density>`; buttons and inputs keep their size so targets stay usable. The choice is saved with the theme and role in the browser. Print is now a real stylesheet: the app switches to the light theme on `beforeprint` and restores the screen theme on `afterprint`, hides the rail, top bar, buttons, table toolbars and dialogs, lifts inner scrolling so a whole page prints, repeats table headings and keeps rows and cards from splitting; external links print their address. A table prints the rows on its current page. 3 unit tests and 2 end-to-end tests added. Not yet done in phase 6: right-to-left and Arabic, tenant theming, and the automated accessibility tests.
- Wave F, Admin Console and vendor portal (tokens and templates only, no redesign): Exchange Rates and Tax gets a summary strip and a data table (region and status filters, search, sort, export) with Release, Reject and Edit staying in the row; the admin log gets a summary strip (entries, chain, tenants touched, latest event) and a data table (tenant and lawful-basis filters, search, hidden-by-default category, IP and hash columns, export); Commitments gets a summary strip. The vendor portal's hard-coded colours (white, near-black panel, mint check) are now tokens, and a progress stepper (Confirm email, Enter code, Second factor, Questionnaire, Submitted) shows where the vendor is. Customers, Billing, Elevation, MFA, Platform Security and the Trust admin pages already use the page template and the tokens and are unchanged. The elevation gates, second-admin approvals, hash-chain checks and every service call are unchanged, and the vendor portal still stores and logs nothing about the vendor. The admin log's JSON and CSV exports now cover the whole log (the on-page filters moved into the table). 3 end-to-end tests added.
- Wave E, the settings group: Integrations, API, Team, Billing and Audit Logs use the shared kit. Integrations gets a KPI strip, a connector table (Connected and Not connected tabs, category filter, search, Sync and Connect buttons staying in the row) and a page per connector at `/ws/integrations/:name`. API keys, webhooks, custom tests and the event stream are data tables; new key, webhook and test are pages (`/ws/api/new-key`, `/ws/api/new-webhook`, `/ws/api/new-test`), the key is still shown once in a dialog after the list is back, and revoke and reveal stay dialogs. Team members are a table with a workspace-role filter and the row opens the person page; inviting is a page at `/ws/team/invite` (role change and approver dialogs unchanged). Billing gets a KPI strip, an invoices table, and plan (`/ws/billingws/plan`) and payment (`/ws/billingws/payment`) pages that still keep display values only. The audit log is a table with category tabs and search; the category chips are gone and the chain view is unchanged. Security Controls is a read-only specification page and is unchanged. The second-admin approvals for write keys and webhooks, segregation of duties and every service call are unchanged. 5 end-to-end tests added; the injection test covers the new URLs and the invite form.
- Wave D, assistant, AI governance and questionnaires: the assistant's answers sit on the AI panel (lavender surface, "AI-assisted", "Review before you rely on this", Copy and Mark reviewed); custom agents, the run log (Waiting, Approved and applied, Rejected tabs) and MCP access are data tables with their row buttons unchanged; Create agent is a page at `/ws/assistant/new`. AI governance gets a KPI strip and an inventory table (status tabs, EU AI Act and guardrail filters, search); an AI system is a page at `/ws/ai/:id` with the drawer's tabs (overview, EU AI Act, impact, bias, signals), registering is a page at `/ws/ai/new` (or `/ws/ai/new/:id` for a discovered system) and editing is `/ws/ai/:id/edit`. Questionnaires get tables for in-flight work and the answer library, a page per questionnaire (`/ws/questionnaires/:id`), and pages for import and add answer. Guardrail, EU classification, impact assessment, bias test, oversight and owner changes, run decisions and answer verification keep their dialogs and rules: the second-person confirmations, the four-eyes approvals and the verify-before-publish gate are unchanged. The vendor role's questionnaire portal is unchanged. The unused `useAiDrawer` hook is gone. 3 end-to-end tests added.
- Wave C, dashboards and charts: Overview, Reports, the Risk dashboard and Frameworks use the shared KPI strip and charts. Overview and Reports get a KPI strip and the accessible line chart and ranked bars (each chart is a figure with a caption, a text summary and a hidden data table; the framework readiness and issue-severity bars say their value in text); the Risk dashboard gets a KPI strip (open, above appetite, awaiting approval, accepted, no control mapped) and a donut of the current rating mix, and its clickable heat map, distribution tables and breakdown bars are unchanged. Frameworks is now a library table (KPI strip, kind tabs, region filter, search, sort, export; readiness bar, status and scope toggles stay usable in the row without opening it); a framework is a page at `/ws/frameworks/:id` with a KPI strip and a requirement-status donut above its groups and requirements, and "Add a regulation, standard or guideline" is a page at `/ws/frameworks/new`. Requirement mapping, applicability and gap-export behaviour are unchanged. The overview, reports and framework hard-coded demo trends and deltas are unchanged; no target value was invented. 4 end-to-end tests added.
- Wave B, Evidence (completes wave B): the list-plus-preview screen is now a register and pages. `/ws/evidence` is a data table (KPI strip, review tabs with counts, type and collector filters, search, sort, export); an item is a page at `/ws/evidence/:id` (review, attachments, version history, notes and the two-person deletion); add and edit are form pages at `/ws/evidence/new` and `/ws/evidence/:id/edit`. Accept and reject, deletion request and decision, attach file and new version stay dialogs. Reviewer separation (nobody accepts evidence they collected, versioned or attached) and the second-admin deletion are unchanged, and approving a deletion returns to the register. 1 end-to-end test added; the injection test covers the new URLs.
- Wave B, Vendors, People and Audits: a vendor and a person are pages (`/ws/vendors/:id` with risk score and procurement gate, certificates, findings, monitoring, applications and reassessment history; `/ws/people/:id` with device posture and owned accounts) and an audit's record page now has the standard header and back link. Add vendor (`/ws/vendors/new`), reassess (`/ws/vendors/:id/reassess`), certificate waiver (`/ws/vendors/:id/waiver`), add contractor (`/ws/people/new`) and new audit (`/ws/audits/new`) are form pages with numbered sections and an unsaved-changes guard. Add certificate, flag finding, change tier, reset MFA, offboarding, and the audit request, finding and closure dialogs stay dialogs. Gates, four-eyes approvals, segregation-of-duties reasons and service calls are unchanged. A vendor in the bell opens its record, the Team module links to the person page (`useOpenPerson` replaces `openPersonDrawer`), and the dead `useVendorDrawer` hook is gone. The injection test covers the new URLs and forms. 3 end-to-end tests added.
- Wave B, Issues and Controls: an issue, a control and an automated test are pages. `/ws/issues/:id` (progress stepper, status and closure workflow, root cause, tasks, links), `/ws/controls/:id` (status, exceptions, linked tests, attestation, mappings) and `/ws/controls/test/:id` replace their drawers. Create and edit are form pages with numbered sections: `/ws/issues/new`, `/ws/issues/:id/edit`, `/ws/controls/new`, `/ws/controls/test/new` and `/ws/controls/:id/exception` (request an exception or waiver). Leaving a form with typed work asks first. Workflow actions, segregation-of-duties reasons (a different verifier closes a High or Critical issue; a different admin or owner decides an exception) and service calls are unchanged; the short decisions (add task, link, closure note, delete, attestation, mapping, status change, exception decision) stay dialogs and the page behind them updates. A failing control or overdue issue in the bell now opens its record. The breadcrumb labels Tests and Request exception. Framework and risk pages link to a control's page (`useOpenControl` replaces `useControlDrawer`). The injection test covers the new URLs. 4 end-to-end tests added.
- Wave B pilot, Policies: a policy is now a page. `/ws/policies/:id` replaces the drawer (progress stepper, details, workflow actions, version history, acceptance, mapped controls, change log timeline), and creating and editing are form pages at `/ws/policies/new` and `/ws/policies/:id/edit` with numbered sections. Record links can be shared and the browser Back button works. Leaving a form with typed work asks first (back link, sidebar and browser Back; the tab-close prompt is the browser's). The workflow actions, their segregation-of-duties reasons and the service calls are unchanged; the short decision dialogs (approve, reject, withdraw, emergency publish, submit for review, reassign owner, map control) stay dialogs. Routes gain a third segment (`sub`), the breadcrumb shows the record, `Page` takes a `back` link, and the kit gains `FormSection`, `FormActions` and `FormMessage`. The injection test now also exercises form pages and the new policy URLs. 5 end-to-end tests added.
- Wave A of the module migration: the registers now use the shared data table with search, filter chips, sortable columns, row select and export. Controls (list and tests), Policies, Third Parties, People, Access (account inventory and requests), Audits (stage tabs) and Commitments are migrated; Policies and People gain KPI strips, and the Third Parties tier cards are real toggle buttons (`aria-pressed`). Existing row actions (Approve, Deny, Reset MFA) are unchanged, keep their segregation-of-duties reasons and do not open the row. The table gained search, a match rule for multi-value fields with display labels, and visually hidden action headers. A squashed "New vendor requests" card was fixed. Held back: Evidence (list plus preview, moves with the detail views in wave B), the cross-framework matrix and the review checklists, which are not registers. 3 unit tests and 7 end-to-end tests added; the read-only helper ignores status tabs (an "Approved" filter tab is not a decision control).
- Shared kit, phase 3 of the design upgrade (`docs/architecture/DESIGN_SYSTEM.md`): `DataTable` (status tabs with counts, filter chips, sortable headers with `aria-sort`, row select with a bulk toolbar, Export selected as formula-safe CSV, pagination, columns and row menus, state kept per table), `KpiStrip`, `KpiTile`, `KpiCard` and `DeltaPill`, `AIPanel`, `Stepper`, `Timeline`, `Switch`, `Segmented`, `Skeleton`, and `LineChart`, `BarChart`, `HBarList` and `DonutChart` (each a figure with a summary, a hidden data table, focusable marks and a legend). The Issues register now uses the data table and a KPI strip. Popovers accept a role, a label and start alignment. The label class is `.eyebrow` because Tailwind's `overline` utility draws a line over text (the phase 1 `.overline` helper, which nothing used, is renamed). 31 unit tests and 6 end-to-end tests added.
- Shell, phase 2 of the design upgrade: the bell opens a notifications slide-over (All, Approvals and Alerts tabs, grouped, Mark all read with Undo, unread badge) built from live data and limited to modules the role can open; items open the record to review and nothing is approved from the panel. Toasts accept an action (Undo), stay 7 seconds and pause on hover or focus. Added Ctrl or ⌘ plus J (AI Assistant, with an Ask AI button for roles that have it) and plus / (shortcut list), My workspace and Keyboard shortcuts in the profile menu, a search landmark, and a 72px collapsed rail with 16px nav tiles. 4 unit tests and 4 end-to-end tests added.
- Design system, phase 1 of the Flow-System-Design upgrade (`docs/architecture/DESIGN_SYSTEM.md`): tokens now follow the blueprint. Violet brand (`--c-brand-*`, the only brand channel), warm paper canvas, opaque flat panels (the glass blur and the ambient gradient are gone), pill controls, 10px fields, 16px cards, 20px popovers, 24px modals, cool low-alpha shadows, 150ms motion, a derived dark theme, and Geist and Geist Mono self-hosted from `public/fonts` (SIL OFL 1.1; the CSP is unchanged). Existing names (`--bg`, `--ink`, `--accent`, ...) are kept as aliases so no module needed editing. Contrast was computed for both themes: the legacy `--faint` grey is darkened to `#686970` (the blueprint's `#909097` fails AA and carries real text here), warning text uses `#8a5000`, and the focus ring is a solid 2px blue outline. Added the `--mono`, `.overline`, `.tabular` and `.mono` helpers and Tailwind utilities for the blueprint ramps. No behaviour change. The vendor-portal privacy test now also allows same-origin `/fonts/*.woff2` requests (still no API or third-party request).
- Performance: every module is now its own chunk, loaded with `next/dynamic` in `src/features/registry.ts` when its route is first opened, instead of all 29 modules shipping with every page. First-load JavaScript (gzipped, transferred) drops from 447 KB to about 250 to 280 KB. Measured locally in headless Chromium with a 4x CPU slowdown, median of 3 runs: on a slow 4G profile (1.6 Mbps, 150 ms latency) page load falls from about 2.98 s to 1.92 s and largest contentful paint from about 3.3 s to 2.5 s; on a fast link largest paint falls from about 0.94 s to 0.76 to 0.85 s. First visits to other modules were unchanged (about 115 to 210 ms). Computed styles of 14,744 elements across 36 routes are identical.
- `front-end/src` is organised by feature: `components/modules/*` became `src/features/<name>/` (34 features, each with its entry, subcomponents and its private `services/`, `lib/` and `data/`), the registry moved to `features/registry.ts`, and components several features share moved to `src/components/kit/`. Each feature has an `index.ts` public API, and ESLint forbids deep imports into another feature, relative reaches across features and shared code importing a feature. No behaviour change: typecheck, lint, 189 unit tests, the build and 96 e2e tests pass, and computed styles of 14,744 elements across 36 routes are identical to `main`. Protected files did not move.
- `front-end/tsconfig.json`: removed `baseUrl` and made the `@/*` path mapping relative (`./src/*`). Behaviour is identical on TypeScript 5.5.3; it removes the config error that TypeScript 6 deprecates and TypeScript 7 rejects (prepares the TypeScript upgrade).
- Tailwind CSS 3.4.6 → 4.3.4 (with `@tailwindcss/postcss`; `autoprefixer` removed, Tailwind 4's optimiser adds the prefixes). CSS-first setup: `tailwind.config.js` is replaced by `@theme` and explicit cascade layers in `src/styles/globals.css`. The legacy donut chart class `ring` is renamed `donut` because it collided with Tailwind's `ring` utility. Verified: computed styles of all 14,744 elements across 36 routes are identical before and after. Dependabot no longer ignores the Tailwind major.
- CI: the Chromium install step refreshes the package index and retries up to 3 times. One run failed because the Ubuntu archive index did not load on a runner image (every font package "unable to locate"); tests themselves are never retried.
- Lint is clean: 63 warnings cleared (unused imports and variables, unused disable directives, `any` replaced with real types, in-app links use `next/link`, in-place state mutations and set-state-in-effect patterns removed). No rule is downgraded and `npm run lint` fails on any warning (`--max-warnings=0`). The elevated-session clock in `src/lib/elevation.ts` no longer sets state in an effect: its clock is floored at the session's `startedAt`.
- Documentation moved into `docs/architecture/`, `docs/guides/` and `docs/security/`; `front-end/docs/` no longer exists.
